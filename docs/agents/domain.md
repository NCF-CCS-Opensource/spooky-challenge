# Domain docs

## Layout and reading rules

This repository uses a single-context layout: `CONTEXT.md` at the root and architectural decision records in `docs/adr/`.

Before exploring, read the root `CONTEXT.md` and ADRs relevant to the area. If a root `CONTEXT-MAP.md` exists later, follow it to the relevant per-context `CONTEXT.md` files and check `src/<context>/docs/adr/` as well as root ADRs.

If these files are absent, proceed silently. The domain-modeling skill creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issue titles, proposals, hypotheses, and tests. Reconsider unfamiliar terms; note real glossary gaps for domain-modeling.

If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be reconsidered.
